## Boundary, registration and prerequisites

Implementation belongs to the independently distributed Keysight package. Reuse the existing neutral Counter catalog and complete-message connector contracts; a custom external backend owns the native command grammar and parser. Shared core receives no HP conditions or registry entries.

The canonical factory ID is `keysight.hp5334b`. Exact passive identity requires manufacturer `HP` or `Hewlett-Packard` and model `5334B`. Match only the explicit `hpib` endpoint scheme, whose opaque address is handled by the supplied connector. No wildcard, generic SCPI fallback, identity probe or reset is sent at registration or open. The application may instead explicitly select the canonical factory through the runtime's existing selection policy.

The application must commission addressed REMOTE operation, native command language, ordinary internal gating, external start/stop arming disabled, 100-gate averaging disabled and suitable input conditioning before opening; the instrument ignores commands in LOCAL (3-76). The configuration API makes native/internal-gating confirmation explicit. The application owns exclusive access: front panel or other controllers must not alter the instrument during a session. Complete-message IO must enforce a finite timeout and bound each ASCII response before allocation; 256 bytes is the documented recommended host policy, not a hardware specification. It must preserve spaces within the response body and remove only framing CRLF.

The driver does not advertise QueryIdentity: paragraph 3-323 (3-80) gives shared `HP 5334A/B`, whereas the example on 3-90 differs. Application-supplied exact model identity avoids relying on that contradiction. Logical channel starts at A; physical channels 1=A and 2=B are supported. Optional channel C is deferred rather than inferred from model name.

## Supported operations

| Neutral operation | Defined behavior | Manual evidence |
|---|---|---|
| CounterSelectChannel(channel) | Pure logical selection, no IO. Accept 1 or 2; otherwise InvalidArgument. | 3-82, FN1/FN2 |
| CounterMeasureFrequency | Fresh measurement on selected A or B; return Hertz. | 3-80/81 and 3-82, FN1/FN2; 3-84/85 |
| CounterMeasurePeriod | Fresh period on A; return Second. Selecting B then requesting period returns UnsupportedOperation before IO. | 3-82, FN4 |
| CounterSetGateTime(seconds) | Inclusive finite range 0.001–99.999 s; write GA, cache only after success. No clamping. | 3-80, paragraph 318; 3-83 |
| Reset, including catalog Reset | Explicit IN initializes power-on state; on successful write, logical channel becomes A and explicit gate cache is cleared (power-on gate is 0.3 s). | 3-80/81, paragraphs 324–325 |

No other operations are advertised. Totalize, optional C, ratios, interval/pulse/rise/fall/voltage measurements, split displays, high-speed binary output, calibration and external arming are deferred. SafeShutdown is not advertised: resource-only close does not disable the instrument's reference/clock outputs. Use resource-only close for this measurement-only driver; do not treat it as bench power isolation.

## Exact transaction semantics

Each measurement holds one runtime lease over the entire query and parse. Its single command body is:

- Frequency A: `FN1,HS0,MD1,WA1,RE`.
- Frequency B: `FN2,HS0,MD1,WA1,RE`.
- Period A: `FN4,HS0,MD1,WA1,RE`.

When gate time was explicitly set in this session, insert `GA<value>,` immediately before RE, e.g. `FN1,HS0,MD1,WA1,GA1.00000000000E-02,RE`. This reapplies the requested gate after function selection, avoiding any assumption about unverified function-preset persistence. Before a gate setter, no promise is made that a front-panel gate setting survives function changes. Setter and reapplication use invariant scientific notation with twelve significant digits and uppercase E, within the documented numeric input limit (3-79). Precision beyond the instrument's resolution is not promised.

Function selection precedes math normalization so MD1 is not issued in an unrelated prior function. HS0 selects normal ASCII (3-80, paragraph 322); MD1 disables math (3-83); WA1 holds the completed measurement for the controller (3-81, paragraph 331); RE clears the current measurement and restarts it (3-81, paragraph 326). Comma separators are documented on 3-78, paragraph 307. Existing `query(nonempty body)` means write this body and read one complete response; no IEEE 488.2 question-mark query is implied. These measurement calls deliberately change function, math, high-speed and wait settings. There is no automatic retry.

## Parser contract

The connector returns one ASCII body without CRLF. An ordinary record is exactly 19 characters: F for Hertz or S for Second, a right-justified 14-character mantissa field, and E followed by sign and two exponent digits (3-84/85). Spaces may precede an explicit + or - mantissa sign; require one digit before the decimal, a nonempty fractional part when a decimal is present, and no whitespace inside the numeric token. The decimal point may be omitted when it would immediately precede E. Parse with invariant ASCII grammar and require a finite result.

The documented zero exception is accepted separately: expected prefix followed by one or more spaces and exactly `0E+00` (3-84). It may be shorter than 19 characters. Example ordinary frequency record `F   +4.58341265E+05` yields 458341.265 Hertz. Equivalent S records yield seconds; they must not be accepted in a frequency operation.

Exact overflow body `O+9.99999999999E+99` uses letter O and returns Quantity(Value=0, expected unit, Status=Overload), where zero is only a placeholder. Reject other O records, wrong type, non-ASCII/control characters, embedded CRLF, malformed exponent or mantissa, unsupported split display, overlong/trailing data and NaN/Infinity as Parse. This is the native parser, not a permissive generic floating-point parser.

## Lifecycle and execution modes

Factory metadata and required-operation validation are pure and frozen before connector open. Sync and dedicated-worker modes use a sync connector; native async is advertised only with a supplied native connector. Rust and C# expose identical behavior and errors. Native implementations await native host IO; no blocking shim or detached host accesses after cancellation. Cancellation before IO produces no IO; cancellation during uncertain IO requires recovery before reuse.

The runtime serializes complete operations and quarantines transport, timeout, partial-response and parse failures. This backend does not offer recovery: TE only clears a status flag, IN/selected clear cannot clear every instrument fault, and a generic drain does not prove native state is usable (3-87/88). Recover returns SessionNeedsRecovery without IO. Reopen only after explicit external resynchronization/commissioning. No implicit IN, TE, bus local, shutdown or retry is issued on failure or close.

Owned resources are closed exactly once, including failed acquisition after ownership transfers; borrowed resources are preserved. Backend drop/dispose is resource-only and idempotent. Reset is never used as recovery for a quarantined session.

## Model-specific review

5334B does not implement 5334A MR/MS commands (3-80, paragraph 319). Option 700 may start in CIIL according to its jumper; native-language confirmation is required, and unknown/CIIL mode is rejected before IO. GAL is not sent automatically; language selection is an application commissioning step (3-89). Rear DIP switch address setup remains external.
