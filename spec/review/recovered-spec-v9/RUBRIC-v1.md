# HP device additions — Council rubric v1
Scope: six model-specific specifications, followed by corresponding implementations: HP5334A, HP5334B, HP3497A, HP8920A, HP8920B, HP8921A. Each model requires independent full-category spec review before implementation and full-category implementation review afterward. Shared family evidence is acceptable only with explicit verified differences/equivalence. Main contains neutral contracts/standard tooling; vendor behavior stays in external Keysight package. No hardware validation or release claim without evidence.

Council: three independent gpt-6.1-sol members, explicit high reasoning; facilitator does not vote. Every category >=9.2/10, precision 0.1. Full three ballots required, median and >=2 threshold-derived votes per category. UNVERIFIED required evidence means incomplete. Demonstrated mandatory defects block regardless of grades. No overall averaging/carryforward. Read-only reviews of identical frozen revisions (tracked file hashes and research/spec evidence manifest). Keep member framing fixed. Regrade all categories after corrections. A rubric change requires new ballot and full regrade.

Categories (all target >=9.2):
- EVIDENCE: primary-manual model/revision/page traceability for commands, responses, units, option limits and differences. Required capability surface and explicitly deferred functions clearly distinguish implementation, simulation and hardware evidence. Uncertain behavior cannot be presented as supported.
- API: useful coherent user-facing capabilities; neutral contracts with typed arguments/results, units/channel semantics, capability gating and explicit model/inventory binding. No proprietary exceptions in shared core; no hidden probing; all six remain scope.
- PROTOCOL: exact verified grammar/framing/parser/error/status/timeout/recovery semantics; unsafe output changes opt-in; option/module/language preconditions validated; bounded input, malformed/overload behavior, cancellation/desynchronization and ownership addressed.
- PARITY: Rust and .NET equivalent public behavior/operation support/error classes; sync, worker async, native async accurately supported/explicitly unavailable; no reflection/dynamic discovery; executable linux-x64 and win-x64 Native AOT strategy and proof appropriate to implementation.
- VALIDATION: spec has executable acceptance matrix; implementation has meaningful exact transcript/parser/negative/model-difference/option-boundary/lifecycle tests, independently checked fixtures and affected regression/generation checks. Fake tests never substitute hardware. Build/package content and static consumer evidence scoped to changes.
- DELIVERY: independently distributed external package, deterministic static registration/selection/capability freeze; usable examples and prerequisites, release/compatibility/limitations documentation, reproducible CI and provenance. Existing distributions not misrepresented as containing new code; no unauthorized publication.

Scoring anchors applicable to each category: 0-4 absent/incorrect; 5-7 partial with substantial gaps; 8.0-9.1 useful but material evidence/design/validation gaps; 9.2-9.5 complete and independently inspectable for declared scope with minor documented limits; 9.6-10 unusually comprehensive and robust. At spec stage grade the specified design and concrete planned acceptance evidence, not nonexistent implementation proof, but require manual-backed wire examples and testable cases. At implementation stage inspect actual source, test outputs, generated artifacts and executable consumer/CI evidence; a plan cannot stand in for execution.

Required review response: member/model/effort, rubric and frozen artifact revision, numeric score and threshold-derived vote EACH category; evidence/limitations/confidence; prioritized concrete changes with locations; unmet mandatory conditions and requested rubric amendments. Before grading give explicit APPROVE or REQUEST_CHANGES rubric ballot with reasons and exact amendments. No other members' assessments supplied until all independent reviews collected.
